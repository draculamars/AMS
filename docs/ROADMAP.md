# Atlas 功能规划与交付边界

Atlas 是个人工程与知识管家。目标是可视化获取项目的结构、内容、关联、版本、迭代、文档、模型和开发过程，并能管理、修改、备份、恢复。每个节点展示自身可用状态，机器名称、路径、存储和连接参数均可配置。

## 已有能力（0.4）

- 项目工作台、目录树、搜索、上传下载、文本差异确认与版本快照。
- 文档、图片和模型预览；模型工程保持装配、材质、引用和入口关系。
- Git 提交、分支、差异、历史内容；原仓库 commit/push 在各工程中进行。
- Codex 公开会话事件、轮次、文件修改证据、变更说明和来源关联；自动关系区分明确证据与推断。
- 本节点工作目录核对、SSH 同步完整映射后发布、归档节点浏览、部署和回退工具。

## 后续里程碑

1. **备份策略与完整灾难恢复**：可配置周期、保留和清理预览、容量预算、失败重试、恢复密钥托管方案；离线/异地第二副本；整项目与整节点恢复演练；按应用适配数据库、权限与路径修复。
2. **开发与产物关系深化**：跨会话迭代时间线，需求—修改—验证—产物关联，脚本生成物和构建证据，关系置信与人工确认，变更影响分析；保留事件原始出处，避免把时间相邻当作依赖。
3. **工程和模型工作空间**：更完整的 CAD/EDA/仿真/数据工程适配，装配层级、模型版本对比、依赖完整性、可复现转换记录；图谱与树联动，浏览器端轻量预览和可配置服务端转换。
4. **统一管理与知识检索**：跨项目、会话、版本和模型的检索，基于证据的问答，收藏和工作集合，插件/技能整包版本、引用跳转、作用范围与实际使用记录。
5. **多节点与公网产品化**：节点注册、同步策略、冲突处理、断线状态、权限、审计、域名 HTTPS 和发布通道。域名/目标就绪后完成公网验收；Mac、Ubuntu 原生或容器部署，桌面和移动浏览器访问。

## 持续验收原则

每个可见结论应指向证据：来源节点、路径、采集时间、版本、哈希、事件或人工确认。未采集的历史标为未知；未归档内容不标可恢复；未验证恢复点不标已验证。任何迁移或首次 Git 初始化保留逐项目方案确认。原始文件修改与资产库更新有清楚边界，并提供差异与恢复路径。

部署和备份成功分别验收。应用能启动不代表数据已备份；仓库校验通过不代表整套应用可以直接跨平台接续运行。每次交付记录源码提交、发布版本、测试结果、备份恢复点、校验范围和剩余限制。
